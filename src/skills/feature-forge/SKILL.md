# feature-forge

针对毕业设计的需求定义 skill。**当 graduation-project 进入阶段 1（需求确认）时调用**。

---

## 0. 核心原则

1. **不替用户做决定** — 只提供结构化的选项，让用户选
2. **分批确认** — 一次 3-5 个问题，不搞疲劳轰炸
3. **记录在案** — 确认后输出功能需求确认单
4. **脚手架优先** — 能用脚手架已有功能的，不做重复开发

---

## 1. 题目分析（Step 1）

拿到毕设题目后，输出三层拆解：

```
题目：《XXX》

┌─ 业务领域
│  谁用这个系统？解决什么问题？
│
├─ 核心功能
│  哪些是"没它不行"的功能？
│  哪些是"锦上添花"的功能？
│
└─ 技术倾向
    题目有没有暗示特定技术？
    （如"基于大数据"→ 需要统计图表）
```

---

## 2. 用户角色定义（Step 2）

**模板**：

```
这个系统需要几种用户角色？

常见的毕设角色组合：

A. 单角色（只有普通用户）
   适用：博客、记账、问答

B. 双角色（普通用户 + 管理员）
   适用：商城、医院挂号、图书管理、课程平台

C. 三角色（学生 + 教师 + 管理员）
   适用：在线教育、教务系统、选课系统
```

---

## 3. 功能模块清单（Step 3）

### 3.1 脚手架已提供（不需重复开发）

| 模块 | 功能 | 代码位置 |
|------|------|---------|
| 用户管理 | 注册/登录(JWT)/CRUD/批量操作 | 全部后端 + 全部前端 |
| 公告管理 | CRUD/分页/富文本 | 同上 |
| 操作日志 | 自动记录/条件查询/删除 | 同上 |
| 文件上传 | 单文件/批量/类型校验 | 同上 |

### 3.2 需用户确认的业务模块

根据题目，列出候选模块让用户选择。以"在线教育平台"为例：

```
在线教育平台可能需要的功能模块：

□ 课程管理 — 发布/编辑/上下架课程
□ 章节管理 — 课程下的视频/文档章节
□ 学习进度 — 记录用户观看进度
□ 考试/测验 — 选择题/判断题 + 自动评分
□ 讨论区 — 课程下的问答讨论
□ 学习统计 — 学习时长/完成率图表

请选择核心模块（建议 ≤ 3 个，答辩够用就行）
```

---

## 4. 边界确认（Step 4）

```
最后确认：

□ 需要对接外部系统吗？
  （短信验证码 / 邮件通知 / 微信支付 / 第三方登录）
  → 建议：毕设不需要真实对接，前端模拟即可，论文写"预留接口"

□ 需要数据统计/图表吗？
  → 如果有，前端用 ECharts（已内置），后端加统计 SQL

□ 有哪些明确不需要的功能？
  → 记录在"排除清单"中
```

---

## 5. 输出格式

```markdown
# 《XXX》功能需求确认单

## 技术方案
- 前端：[React/Vue-Antd/...]
- 后端：[Go/SpringBoot/...]
- 数据库：scaffold_db

## 用户角色
- [角色A]：[权限描述]
- [角色B]：[权限描述]

## 复用脚手架模块
- [x] 用户管理
- [x] 公告管理
- [x] 操作日志
- [x] 文件上传

## 新增业务模块
- [ ] [模块1]：[核心功能点]
- [ ] [模块2]：[核心功能点]

## 新增数据表（预估）
| 表名 | 字段概要 |
|------|---------|
| xxx  | id, name, ... |

## 排除清单
- [x] 不做的：[原因]

---
⬆️ 确认后开始开发
```

---

## 6. 与 graduation-project 的配合

本 skill 被 `graduation-project` 在**阶段 1（需求确认）** 时调用，产出功能需求确认单。确认单是后续所有开发的唯一依据。
